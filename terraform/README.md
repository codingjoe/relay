# Deploy relay on Hetzner with Terraform

This guide covers provisioning a Hetzner Cloud server with multiple IPs
for email deliverability, and deploying relay via the-box (Docker Compose)
with GitHub Actions CI/CD.

## Architecture

```
Internet → Primary IP (relay.example.com)
             ├── :443 → Caddy → web (Django)
             ├── :53  → DNS (authoritative)
             └── :25  → MX (incoming mail)

Internet → Floating IP 1 (smtp.example.com)
             └── :587 → SMTP (outgoing mail)

Internet → Floating IP 2 (smtp2.example.com)
             └── :587 → SMTP backup (blacklist rotation)
```

Each IP has its own PTR record. If one SMTP IP gets blacklisted, switch
DNS to the backup IP and update `RELAY_DNS_SMTP_IPS`.

## Prerequisites

1. **Terraform** installed (`brew install terraform` or
   [terraform.io](https://developer.hashicorp.com/terraform/install)).

1. **A Hetzner Cloud API token** with Read & Write permissions
   (Console → Security → API Tokens).

1. **Your SSH public key** (for root access to the server).

1. **GitHub CLI** (`gh`) installed and authenticated, for the-box setup.

1. **dotenvx** installed (`npm install -g @dotenvx/dotenvx`).

1. **A DNS domain** with A record access.

## Step 1 - Provision the server with Terraform

```bash
cd terraform

# Create a terraform.tfvars file
cat > terraform.tfvars <<EOF
hcloud_token = "<your-hetzner-api-token>"
hostname     = "relay.example.com"
server_type  = "cx22"
server_location = "nbg1"
ssh_public_keys = ["$(cat ~/.ssh/id_ed25519.pub)"]
smtp_floating_ip_count = 2
EOF

terraform init
terraform plan
terraform apply
```

Terraform provisions:

- A Hetzner Cloud server (CX22, Ubuntu 24.04)
- 2 floating IPs for SMTP (blacklist rotation)
- PTR records for the primary IP and each floating IP
- A deployment SSH key pair (generated by Terraform)
- Cloud-init that installs Docker, creates the `github` and `collaborator`
  users, and configures the floating IPs on the network interface

Note the outputs:

```bash
terraform output -raw server_ip
terraform output -raw ssh_private_key > /tmp/deploy_key
terraform output smtp_ips
```

## Step 2 - Configure DNS

Create A records pointing to your server IPs:

```
A  relay.example.com    <server_ip>
A  smtp.example.com     <smtp_ips[0]>
A  smtp2.example.com   <smtp_ips[1]>
A  mx.example.com       <server_ip>
A  dns.example.com      <server_ip>
A  *.relay.example.com  <server_ip>
```

The PTR records are already set by Terraform:

- `<server_ip>` → `relay.example.com`
- `<smtp_ips[0]>` → `smtp.example.com`
- `<smtp_ips[1]>` → `smtp2.example.com`

## Step 3 - Set up the-box GitHub integration

The-box needs GitHub variables and secrets to deploy via SSH. Run:

```bash
# Get the server IP and SSH key from Terraform outputs
SERVER_IP=$(cd terraform && terraform output -raw server_ip)
SSH_PRIVATE_KEY=$(cd terraform && terraform output -raw ssh_private_key)

# Set GitHub variables
gh variable set SSH_HOSTNAME --body "$SERVER_IP"
gh variable set SSH_KNOWN_HOSTS --body "$(ssh-keyscan "$SERVER_IP")"
gh variable set HOSTNAME --body "relay.example.com" --env production

# Set GitHub secrets
echo "$SSH_PRIVATE_KEY" | gh secret set SSH_PRIVATE_KEY
```

## Step 4 - Encrypt production environment

Create the encrypted `.env.production` with dotenvx:

```bash
dotenvx set HOSTNAME "relay.example.com" -f .env.production -p
dotenvx set POSTGRES_PASSWORD "$(python3 -c 'import secrets; print(secrets.token_urlsafe())')" -f .env.production
dotenvx set REDIS_PASSWORD "$(python3 -c 'import secrets; print(secrets.token_urlsafe())')" -f .env.production
dotenvx set RELAY_DNS_SMTP_IPS "$(cd terraform && terraform output -raw smtp_ips | jq -r '.[0]')" -f .env.production
dotenvx set GITHUB_CLIENT_ID "<your-github-oauth-client-id>" -f .env.production
dotenvx set GITHUB_CLIENT_SECRET "<your-github-oauth-client-secret>" -f .env.production
dotenvx set SECRET_KEY "$(python3 -c 'import secrets; print(secrets.token_urlsafe())')" -f .env.production

# Set the dotenvx private key as a GitHub secret
dotenvx get DOTENV_PRIVATE_KEY_PRODUCTION -f .env.keys | gh secret set DOTENV_PRIVATE_KEY_PRODUCTION
```

Commit the encrypted `.env.production` to the repository:

```bash
git add .env.production
git commit -m "Add encrypted production environment"
git push
```

## Step 5 - Trigger the first deploy

Push to main triggers CI (builds and pushes the Docker image to ghcr.io),
then the deploy workflow runs automatically:

```bash
git push origin main
```

Or trigger manually:

```bash
gh workflow run deploy.yml --ref main
```

Monitor the deployment:

```bash
gh run watch
```

## Step 6 - Verify the deployment

Check the web UI:

```bash
curl https://relay.example.com/health/
```

Test SMTP connectivity:

```bash
openssl s_client -connect smtp.example.com:587 -starttls smtp
```

Test DNS:

```bash
dig MX example.com @dns.example.com
```

## IP reputation and blacklist rotation

Each SMTP IP builds reputation over time. If an IP gets blacklisted:

1. **Update DNS** - point the SMTP A record to the backup IP:

   ```
   A  smtp.example.com  <smtp_ips[1]>
   ```

1. **Update `RELAY_DNS_SMTP_IPS`** in `.env.production`:

   ```bash
   dotenvx set RELAY_DNS_SMTP_IPS "<smtp_ips[1]>" -f .env.production -p
   git add .env.production
   git commit -m "Switch SMTP IP for blacklist rotation"
   git push
   ```

1. **Monitor** - check blacklist status at
   [MXToolbox](https://mxtoolbox.com/blacklists.aspx).

1. **Wait** - keep the blacklisted IP assigned but unused until it is
   delisted. Do not delete the floating IP; reputation recovers over time.

## Adding more SMTP IPs

To add more floating IPs for additional rotation capacity:

```bash
cd terraform
# Update terraform.tfvars
# smtp_floating_ip_count = 3

terraform apply
```

Then set PTR and DNS for the new IP:

```bash
# PTR is set automatically by Terraform
# Add DNS A record manually:
# A  smtp3.example.com  <new_ip>
```

## GitHub Actions CI/CD

The CI/CD pipeline uses the-box's deploy action:

- **CI** (`ci.yml`): Builds and pushes the Docker image to ghcr.io on every
  push to main.
- **Deploy** (`deploy.yml`): Runs after CI completes. SSHs into the server,
  pulls the latest image, and runs `docker compose up -d`. Secrets are
  decrypted on the server using `DOTENV_PRIVATE_KEY_PRODUCTION`.

**Required GitHub variables:**

- `SSH_HOSTNAME` - server IP
- `SSH_KNOWN_HOSTS` - SSH host key fingerprint
- `HOSTNAME` - production hostname (environment variable)

**Required GitHub secrets:**

- `SSH_PRIVATE_KEY` - deployment SSH private key
- `DOTENV_PRIVATE_KEY_PRODUCTION` - dotenvx private key

## Troubleshooting

### Server not reachable

```bash
ssh root@$(cd terraform && terraform output -raw server_ip)
```

### Floating IPs not configured

Check if the IPs are assigned to the interface:

```bash
ssh root@<server_ip> ip addr show eth0
```

If missing, re-run the cloud-init network script:

```bash
ssh root@<server_ip> /etc/networkd-dispatcher/routable.d/10-floating-ips.sh
```

### Deploy workflow fails

Check the workflow run:

```bash
gh run list --workflow=deploy.yml
gh run view <run-id> --log
```

### SMTP connection refused

```bash
ssh root@<server_ip> docker compose ps
ssh root@<server_ip> docker compose logs smtp
```

### TLS certificate not issuing

```bash
dig relay.example.com
ssh root@<server_ip> docker compose logs caddy
```
